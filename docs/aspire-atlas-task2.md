# Aspire Atlas — Task 2: Find Space

The approved opening stays intact. Its Find Space button enters discovery on the same page and MapLibre instance. Explore restores the opening, all markers and its original camera constraint. No post content, metadata, coordinates, PMTiles, cartographic style, REST representation, theme, Docker configuration or dependencies changed.

## Architecture and files

- `atlas/find-space.php`: frontend-only, initially hidden filter and results shell, included by `atlas/template.php`. Property types and supported transaction choices use `get_terms()` and actual slugs. No duplicated IDs or new terms.
- `atlas/src/filters.js`: pure filtering, SF/metric rules and approximate area presets.
- `atlas/src/find-space.js`: one state owner (`mode`, `filters`, `selectedPropertyId`, `hoveredPropertyId`), accessible controls/cards and the map adapter boundary.
- `atlas/src/find-space.css`: discovery-only styles, imported by the frontend bundle. Existing opening CSS and the static Gutenberg preview are unchanged.
- `atlas/src/view.js`: connects the existing one-time REST load, GeoJSON layers, camera and popup to shared discovery state.
- `atlas/src/properties.js`: adds hover enlargement and feature-state dimming to the existing markers.
- Existing PHP/JS tests are extended; `atlas/build/view.js`, `view.css` and `manifest.json` are regenerated by the existing build.

Data is fetched once per Atlas initialization. All filter changes run against that in-memory collection, using MapLibre layer filters to show matching markers. Cards are generated with DOM text APIs, not imported HTML. Lazy-loaded images use the unchanged REST local-media representation. No prices are rendered, including the suppressed FM 1093 price.

## Filters

- **Property Type:** actual registered terms, including Office Condo; exact slug matching follows the existing singular REST taxonomy representation.
- **Transaction:** For Lease by default, For Sale or Lease, All Transactions. For Lease also admits the actual dual-listing slug because that listing is leasable. The dual option matches only `for-sale-or-lease`; it does not merge independent sale and lease records. The current four records produce two default results, four for All Transactions and zero dual listings.
- **Size:** positive `availableSf` first. Only when it is absent/null, positive `buildingSf` may be used for non-land listings. Explicit zero/invalid available area does not silently fall back. Acreage is never converted. Ranges are nonoverlapping: <5,000; 5,000–<10,000; 10,000–<25,000; 25,000–<50,000; >=50,000 SF.
- **Area:** inclusive approximate coordinate boxes below, independent of other filters. All Houston removes the area restriction. These boxes overlap intentionally and are search conveniences, not official Houston CRE submarkets or parcel boundaries.

## Results and map interaction

The desktop rail is approximately 239px tall and overlays the bottom of Atlas. Horizontal scrolling exposes additional real properties. Each button contains the local image, taxonomy labels, full title, city/state and strongest usable area metric (available SF, non-land building SF, lot acres).

Card pointer hover or keyboard focus highlights its marker and label; marker hover highlights its card. Unrelated markers dim slightly. Card activation selects and eases toward the property at zoom 13.3 over 700ms. Marker activation selects and scrolls only its card rail when needed, without scrolling the document or stealing focus. Selection has both a persistent visual state and `aria-pressed`.

Entry, filter changes and reset fit the matching set. An active area preset frames its approximate region. An empty set without an area leaves the camera alone. Manual map navigation never changes the result set or starts an automatic refit. Navigation controls remain MapLibre's existing controls.

Camera padding accounts for the filter and results rails once (MapLibre adds fit padding to existing edge padding). Find Space uses a broader navigation constraint, [[-97,28.4],[-93.8,31.3]], because the original tight constraint imposed a minimum zoom that hid listings behind the rails on short, wide screens. This is a camera envelope only, not new data coverage. Explore restores its original constraint. The original archive and style are unchanged; detailed tile coverage remains limited to the existing Houston extraction.

## Accessibility, motion and responsive behavior

Native labeled selects, buttons, a semantic property list, live result counts and selection announcements provide the full discovery workflow without dragging the map. Entry focuses the Find Space heading; Explore returns focus to its intent button. Empty-state reset moves focus to the first filter before removing the empty action. The old QA selector is entirely hidden in discovery; the accessible card rail replaces it there. It keeps its prior behavior in Explore.

Reduced-motion preference disables CSS transitions/entrances, sets camera durations to zero, and makes programmatic rail/page scrolling instant. No new library or looping animation is used. The available browser test surface has no media-preference emulation; reduced-motion branches and CSS were checked in source, not through an emulated browser preference.

Filters form a compact desktop command rail, four columns below 1100px, then two columns on mobile. The horizontal results rail remains usable. Narrow screens allow normal document scrolling with space reserved for the map; there is no draggable bottom sheet.
